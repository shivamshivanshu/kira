## Description

`entityschema.ProjectItem` only surfaces struct fields and body sections, not
`ExtraScalars`/`ExtraLists`. `core.validateItem` overlays extras before
validating, but `doctor.RefTypeMismatches` reads `ProjectItem`'s output
directly — so a custom `ref`-type extra field is invisible to the doctor
ref-type check (reads nil, no-ops). Dormant today: built-in entity-target refs
(epic/blocked_by) are struct fields already surfaced. Becomes real with
user-declared ref extras (phase 4).

Fix: make `ProjectItem` surface extras (single source both callers share), so
the two can't diverge. Note the decode nuance — validation wants typed values,
doctor wants the rendered ref string; pick a representation that serves both.

Surfaced during CORE-3 pre-push holistic review.

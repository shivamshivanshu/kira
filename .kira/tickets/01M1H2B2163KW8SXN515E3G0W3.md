`renderCommitSubject` (`internal/core/kiracommit.go`) substituted the
`{date}` template token from `time.Now()` rather than `timex.Now()`, so a
commit subject configured as e.g. `kira: {date}` ignored `KIRA_NOW`. That is
the same class DX-13 fixed for rendered time-relative output, and the
project's own gotchas list names it explicitly: rendered output must read
the clock through `timex.Now()`.

Latent because the `{date}` token was exercised nowhere -- the
`TestRenderCommitSubject` table covers `{count}` and `{numbers}` only.

Fixed, with a test that pins `KIRA_NOW` and asserts the substituted date.
Confirmed the test fails against the previous code (produced the real
current date) and passes with the fix.

Separately: `{date}` is documented nowhere -- it appears in no README, doc
page, or config comment, so a user cannot discover it. Either document it
alongside `{count}`/`{numbers}` or drop it.

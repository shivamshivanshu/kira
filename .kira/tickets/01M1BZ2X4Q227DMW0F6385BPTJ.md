Dropping .kira/schema/foo.json creates nothing. kira create validates the type against cfg.Workflows (cli/create.go:53-55), and items of a workflow-less type warn as orphans (core/load.go:37-45), so a new type still needs a workflows: entry in config.yaml. This quietly narrows the design doc's 'user-defined entity type'.
Decide: let a schema file imply a type (deriving states from the schema's state field, which is already declared there), or document that schema and workflow are two required halves. Related to CORE-39, which moves entity definitions toward files generally.
